# 2026 DVWA 웹 취약점 분석 및 모의해킹 포트폴리오

DVWA 환경에서 웹 취약점을 Low / Medium / High / Impossible 단계별로 분석하고, 소스코드와 HTTP 요청·응답을 비교하며 취약점의 발생 원인과 방어 로직을 확인했습니다.

Brute Force와 CSRF를 직접 담당했으며, 이후 상대 조가 구축한 웹사이트를 대상으로 CSRF 취약점을 분석하고 실제 요청을 통해 공격 가능 여부를 검증했습니다.

단순히 공격 도구를 사용하는 것보다 **취약점 원인 분석 → HTTP 요청 확인 → 공격 검증 → 방어 방식 비교**의 흐름을 이해하는 데 중점을 둔 프로젝트입니다.

---

## 프로젝트 개요

* 프로젝트명: DVWA 웹 취약점 분석 및 웹서버 상호 모의해킹
* 교육기관: 코리아 IT 아카데미
* 수행 형태: 6명 / 2개 조 팀 프로젝트
* 프로젝트 기간: 2026.03.09 ~ 2026.03.20
* 주요 환경: Kali Linux, Rocky Linux, Apache2, MariaDB, Burp Suite

### 담당 역할

* Part I: Brute Force, CSRF 보안 레벨별 분석
* Part II: 상대 조 웹사이트 대상 CSRF 취약점 분석 및 공격 검증

---

## 주요 수행 내용

* DVWA의 Brute Force와 CSRF를 Low / Medium / High / Impossible 단계별로 분석
* 보안 단계가 높아질수록 추가되는 인증·세션·요청 검증 로직을 소스코드와 실제 동작을 통해 비교
* Burp Suite Proxy를 이용해 HTTP Request / Response, Header, Cookie, Parameter 구조 확인
* Burp Suite Repeater를 활용해 요청 값을 변경·재전송하며 서버의 검증 로직 확인
* Brute Force 실습에서 Intruder를 활용해 반복 인증 요청과 성공·실패 응답 차이 비교
* CSRF 실습에서 세션 쿠키, CSRF Token, Origin/Referer 등 요청 검증 요소의 역할 분석
* Part II에서는 상대 조 웹사이트의 소스코드와 정상 요청을 먼저 분석한 뒤 CSRF 취약 여부를 직접 검증
* 취약점의 성공 여부뿐 아니라 **왜 공격이 가능한지, 어떤 방어가 추가되면 공격이 어려워지는지**를 중심으로 결과 정리

---

## 프로젝트를 통해 익힌 점

* **취약점 정의 → 발생 원인 → 요청 구조 확인 → 공격 가능성 검증 → 대응방안 확인**의 분석 흐름 습득
* Burp Suite를 활용해 HTTP 요청·응답, Header, Cookie, Parameter를 직접 확인하며 웹 통신 구조 이해
* 인증과 세션이 존재하더라도 요청의 진위와 사용자 의도를 별도로 검증해야 한다는 점을 실습을 통해 이해
* 정상 요청과 공격 요청을 비교하며 서버가 어떤 값을 신뢰하고 어떤 검증을 수행하는지 분석하는 방식 경험
* 단일 보안 설정이 아닌 여러 통제를 함께 적용하는 Defense in Depth의 중요성 학습
* 팀 프로젝트에서 직접 담당한 영역과 팀원 담당 영역을 구분하고 분석 결과를 공유하는 협업 경험

---

## 핵심 수행 흐름

`취약점 확인 → 소스코드 분석 → HTTP 요청 분석 → 공격 가능성 검증 → 방어 로직 비교`

단순히 공격을 성공시키는 것보다
**왜 취약한지, 서버가 어떤 값을 신뢰하는지, 어떤 검증이 부족한지를 이해하는 데 중점을 두었습니다.**

---

## 한 줄 요약

DVWA와 팀 웹서버를 대상으로 소스코드와 HTTP 요청·응답을 분석하며, 웹 취약점의 발생 원인부터 공격 검증과 방어 방식까지 단계적으로 확인한 모의해킹 프로젝트입니다.
